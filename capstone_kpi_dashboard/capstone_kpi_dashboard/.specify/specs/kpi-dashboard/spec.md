## 1. 개요

### 1.1 목적
조선소의 생산·설비·품질·공정 데이터를 한 화면에 모아, 목표 미달을 빨리 발견하고 원인을 공정·설비·블록 단위로 추적하게 한다.

### 1.2 대상 사용자
- 생산관리 담당자 (기간별 실적과 목표 달성 여부 확인)
- 현장 관리자 (설비 OEE, 블록 지연, 품질 추이 확인)
- 발표 청중 (기능과 KPI 정의 설명)

### 1.3 범위
- **포함**: 데이터 로드, 필터, KPI 5종 계산과 직전 기간 비교, KPI별 상태 경고, 탭 4개 시각화, 가상 데이터 생성 스크립트
- **제외**: 실제 MES·ERP 연동, 자동 알림(메일·메신저), 예지보전 모델, 사용자 인증, 데이터 편집 기능

### 1.4 실행 환경
- Python 패키지: `requirements.txt` (streamlit, pandas, plotly, numpy, pytest)
- 실행: `npm start` (내부적으로 `streamlit run app.py`), 브라우저 `http://localhost:8501`
- 테스트: `npm test` (내부적으로 `python -m pytest tests -q`)
- 데이터 생성: `python generate_data.py`

## 4. 기능 요구사항

### FR-1 데이터 로드와 블록 상태 판정
- 세 CSV를 읽어 `prod`, `eq`, `blk`를 만듭니다. 캐시를 씁니다.
- 블록-공정마다 다음을 계산합니다.
  - `delay_days` = (실적 종료일 또는 기준일 − 계획 종료일)의 일수. 시작하지 않았으면 0. 음수는 0으로 자릅니다.
  - `status`: 실적 시작이 없으면 **대기**, 시작했고 종료가 없으면 **진행**, 종료가 있으면 **완료**. `delay_days > 0`이면 뒤에 **(지연)**을 붙입니다. 예: `완료(지연)`, `진행(지연)`.

### FR-2 필터
사이드바에서 다음 세 가지를 고릅니다.

| 필터 | 기본값 | 적용 대상 |
|---|---|---|
| 기간 (날짜 범위) | 데이터 전체 기간 | 생산(`P`), 설비(`E`) |
| 공정 (다중 선택) | 6개 전부 | 생산(`P`), 설비(`E`), 블록(`B`) |
| 호선 (다중 선택) | 4개 전부 | 블록(`B`)만 |

- 기간을 하나만 고르거나 범위가 비어 있으면 전체 기간으로 봅니다.
- 호선 필터는 블록 데이터에만 적용됩니다. 카드 중 하나와 블록 탭이 여기에 해당합니다.
- **맨아워 효율의 기간 적용**: 블록 데이터는 실적 기간이 선택 기간과 겹치는 행만 씁니다(FR-4 참고). 지연 블록 수는 기간과 무관하게 기준일 기준 현재 상태로 셉니다.

### FR-3 빈 데이터 처리
- 필터 결과 생산 데이터가 없으면 경고 문구 `선택한 조건에 해당하는 데이터가 없습니다.`를 보여 주고 화면 렌더링을 멈춥니다.

### FR-4 KPI 계산

| KPI | 계산식 | 입력 |
|---|---|---|
| 생산계획 달성률 | Σ실적 물량 ÷ Σ계획 물량 × 100 | `P` |
| 설비 종합효율(OEE) | 가동률 × 성능효율 × 양품률 × 100 | `E` |
| 불량률 | Σ불량 건수 ÷ Σ검사 건수 × 100 | `P` |
| 맨아워 효율 | Σ계획 MH ÷ Σ실적 MH × 100 | `B`에서 실적 기간이 선택 기간과 겹치는 행 |
| 지연 블록 수 | `delay_days > 0`인 블록의 고유 개수 (기간 필터 없음, 기준일 기준 현재 상태) | `B` |

- 실적 기간이 선택 기간과 겹친다는 것은 실적 시작일이 선택 종료일 이하이고, 실적 종료일(진행 중이면 기준일)이 선택 시작일 이상이라는 뜻입니다. 실적 시작일이 없는 행(대기)은 제외합니다. 실적 MH는 기간별로 나뉘어 있지 않으므로, 겹치는 행의 실적 MH 전체를 씁니다.

- OEE 세부 계산 (`oee_calc`):
  - 계획 시간 = Σ`planned_min`
  - 가동 시간 = 계획 시간 − Σ`downtime_min`
  - 가동률 = 가동 시간 ÷ 계획 시간
  - 성능효율 = Σ(`ideal_ct_min` × `total_cnt`) ÷ 가동 시간
  - 양품률 = Σ`good_cnt` ÷ Σ`total_cnt`
- 모든 비율은 행별 비율의 평균이 아니라 합계끼리 나눈 가중 비율입니다.
- OEE와 맨아워 효율은 분모가 0이면 0으로 표시합니다.
- 생산계획 달성률과 불량률은 분모가 0이면 계산할 수 없어 NaN이 됩니다. 현재 데이터에서는 이 경우가 생기지 않습니다.

### FR-5 직전 기간 대비 증감
- 직전 기간 = [시작일 − 기간 길이, 시작일 − 1일]. 같은 공정 필터를 씁니다.
- 달성률, OEE, 불량률 카드에 `+x.x%p` 형식의 증감을 표시합니다.
- 직전 기간의 일부만 데이터가 있으면, 있는 데이터만으로 비교합니다.
- 직전 기간 데이터가 전혀 없으면 증감을 표시하지 않습니다.
- 불량률 증감은 값이 올라가면 빨간색(나쁨)으로 표시합니다.

### FR-6 KPI 상태 판정과 경고
- 판정 로직은 `kpi_alerts.py`에 있습니다.

| KPI | 목표 | 방향 | 주의(🟡) 구간 | 미달(🔴) 기준 |
|---|---|---|---|---|
| 생산계획 달성률 | 95 이상 | 높을수록 좋음 | 92 이상 95 미만 | 92 미만 |
| OEE | 75 이상 | 높을수록 좋음 | 70 이상 75 미만 | 70 미만 |
| 불량률 | 3 이하 | 낮을수록 좋음 | 3 초과 3.5 이하 | 3.5 초과 |
| 맨아워 효율 | 95 이상 | 높을수록 좋음 | 92 이상 95 미만 | 92 미만 |
| 지연 블록 수 | 0 | 낮을수록 좋음 | 1 이상 4 이하 | 5 이상 |

- 값이 없으면 ⚪ (데이터 없음)입니다.
- **카드**: 라벨 앞에 🟢 / 🟡 / 🔴 / ⚪ 아이콘을 붙입니다.
- **상단 경고**: 주의·미달인 KPI마다 한 줄씩 표시합니다. 미달은 빨간 박스, 주의는 노란 박스입니다. 줄에는 현재 값, 목표, 목표 대비 차이(예: `-3.8%p`, `+5건`)를 넣습니다.
- 모두 정상이면 `✅ 모든 KPI가 목표를 충족하고 있습니다.` 초록 박스를 표시합니다.
- 차트 기준선은 목표값을 씁니다(달성률 95%, OEE 75%, 불량률 3%).

### FR-7 탭 1 — 📈 생산실적
1. **일별 계획 대비 실적**: 계획·실적 물량 막대(겹침), 달성률 선(오른쪽 축, 40~110%), 목표 95% 점선.
2. **공정별 계획 달성률**: 공정별 달성률 막대(색은 80~100% 빨강→초록). 목표 점선. 달성률이 목표 미달인 공정마다 경고 한 줄을 표시합니다.
3. **공정 × 주차 달성률 히트맵**: 주 단위(월요일 시작) 달성률, 색 범위 60~100%. 선택 기간 양 끝의 부분 주도 그대로 표시하며, 라벨은 그 주의 월요일 날짜입니다(`MM/DD주`).
- 공정 순서는 `절단 → 탑재`로 고정합니다.

### FR-8 탭 2 — 🧱 블록 공정진척
1. **블록-공정 상태 도넛**: 상태(대기, 진행, 완료, 진행(지연), 완료(지연))별 건수.
2. **호선·공정별 평균 진척률**: 호선마다 공정별 진척률 평균을 묶음 막대로 표시합니다.
3. **블록 간트차트**: 블록 선택 목록은 현재 호선·공정 필터를 따릅니다. 블록 하나를 고르면 선택된 공정에 대해 계획(회색)과 실적(파랑)을 가로 막대로 보여 줍니다. 실적 종료일이 없으면 기준일(2026-10-31)까지 그립니다. 기준일 세로선을 표시합니다.
4. **지연 블록 TOP 10**: `delay_days > 0`인 블록-공정을 지연일수 내림차순으로 10건 보여 줍니다. 열은 블록, 선종, 공정, 계획종료, 실적종료, 지연일수, 상태입니다.

### FR-9 탭 3 — 🔧 설비 OEE
1. **OEE 요약 카드 4개**: 가동률, 성능효율, 양품률, OEE (선택한 설비 전체 기준).
2. **설비별 OEE 막대**: 설비마다 OEE를 계산해 낮은 순으로 정렬합니다. 색 범위 50~85, 기준선 75%. 설비 종류를 호버 정보로 보여 줍니다. 설비마다 OEE 경고 한 줄을 표시합니다(목표 미달인 것만).
3. **설비별 일 정지시간 추이**: 날짜 × 설비별 `downtime_min` 합계 선그래프.

### FR-10 탭 4 — 🧪 품질
1. **일별 불량률 추이**: 날짜별 불량률 선, 목표 상한 3% 점선. 상한을 넘은 날이 있으면 "불량률 목표 상한 초과 N일 · 최고 X.XX% (MM/DD)" 경고를 표시합니다. 경고 강도는 최고값 기준입니다.
2. **공정별 불량 파레토**: 공정별 불량 건수 막대(내림차순), 누적 비율 선(오른쪽 축, 0~105%).
3. **총 재작업 시간**: 선택 기간 `rework_hr` 합계(시간 단위, 천 단위 구분).

## 6. 알려진 한계

1. **맨아워 효율은 블록 실적 기간으로 근사한다.** 실적 MH는 기간별로 나뉘어 있지 않습니다. 그래서 선택 기간과 실적 기간이 겹치는 블록-공정 행의 MH 전체를 씁니다. 기간 경계에 걸친 블록은 전체 MH가 들어가므로 정확한 일별 값은 아닙니다. 발표에서는 "블록 단위 근사"라고 설명합니다.
2. **지연 블록 수는 기간과 무관하다.** 기준일(2026-10-31) 기준으로 지금 지연 중인 블록 수를 셉니다. 기간을 바꿔도 값이 같습니다.
2. **헌법 원칙 4와 충돌한다.** 헌법은 날짜를 KST로 표시하도록 정하지만, 현재 화면에는 KST 변환 로직이 없습니다. 데이터는 시각 없이 일 단위라 지금은 날짜를 그대로 표시합니다. 원칙을 지키려면 표시 로직을 추가하거나, 헌법 문구를 일 단위 데이터에 맞게 고쳐야 합니다.
3. **상위 폴더 `app.py` 사본은 실행되지 않는다.** `C:\캡스톤_MK\app.py`는 이 명세의 `app.py`와 같은 내용이지만 `data/` 폴더가 없어 로드에 실패합니다. 이 명세는 `capstone_kpi_dashboard\capstone_kpi_dashboard\app.py`만 대상으로 합니다.
4. **`plan.md`가 아직 없다.** 원칙 2에서 요구하는 외부 패키지 추가 근거 문서가 없습니다.
5. **일부 데이터 이벤트는 난수 기반이다.** 시드가 고정되어 있어 재현은 되지만, 값을 바꾸면 AC-08~AC-10의 숫자가 달라질 수 있습니다.

## 7. 비기능 요구사항

- **사내망 전용**: 실행 중 외부 CDN, 외부 폰트, 외부 API를 쓰지 않습니다 (원칙 5).
- **한국어 화면**: 사용자에게 보이는 문구는 한국어입니다 (원칙 4).
- **개인정보**: 데이터에 이름과 사번이 없고, 로그에 개인 식별 값을 남기지 않습니다 (원칙 3).
- **테스트**: 판정 로직은 단위 테스트, 화면은 앱 스모크 테스트로 확인합니다 (원칙 1).
- **반응 시간**: 기본 기간에서 화면 렌더링이 로컬 환경에서 몇 초 안에 끝나야 합니다. 정량 기준은 측정 후 정합니다 (가정).

## 9. 가정

- 사용자는 Windows 환경에서 Python 3.13과 Node.js(`npm` 명령용)를 쓴다고 가정합니다. 이 명세는 Python 버전을 고정하지 않습니다.
