## 1. 헌법 점검

| 원칙 | 점검 질문 | 결과 | 근거 / 조치 |
|---|---|---|---|
| 원칙 1. API는 테스트가 먼저 | 공개 함수와 엔드포인트마다 테스트가 먼저 있는가 | **통과 (설계 기준)** | `tasks.md`에서 모든 구현 작업 앞에 테스트 작업이 있다. 구현 전에 실패를 확인한다. |
| 원칙 2. 패키지는 꼭 필요한 것만, 근거를 plan.md에 | 새 패키지마다 이름, 범위, 용도, 대체 불가 이유가 있는가 | **통과** | 기술 설계 §2에 `express`, `ejs`, `plotly.js`(파일 복사)의 근거를 적었다. 개발 의존성은 없다. |
| 원칙 3. 이름과 사번은 로그에 남기지 않는다 | 로그인 추가로 생기는 개인정보가 로그와 쿠키에 남지 않는가 | **통과 (설계 기준), 검증 필요** | 기술 설계 §7에서 해시 저장, 쿠키 최소화, 로그 차단을 정했다. AC-21 테스트로 확인한다. |
| 원칙 4. 한국어 화면, KST 날짜 | 새 화면 문구가 한국어인가, 날짜 표시 시간대가 명시되는가 | **통과 (설계 기준)** | 로그인과 검색 화면 문구를 한국어로 쓴다. 날짜 표시 함수는 Asia/Seoul을 명시하고, 테스트를 함께 둔다. 데이터는 일 단위라 시각 변환은 필요 없다. |
| 원칙 5. 사내망에서만 동작, CDN 금지 | 외부 URL을 불러오는 코드나 자원이 있는가 | **통과 (설계 기준), 검증 필요** | Plotly.js는 `public/vendor/`에 둔다. AC-16 테스트와 grep으로 확인한다. 라이선스 확인은 보류 중이다 (기술 설계 R6). |

**점검 결과: 위반 없음.** 원칙 3, 5는 구현 후 테스트로 검증해야 통과가 확정된다.

## 2. 2단계 명세에 맞춘 변경점

기술 설계(`kpi-dashboard/plan.md`)에서 바뀐 부분은 다음과 같다.

| 항목 | 기술 설계 | 2단계 명세 | 변경 |
|---|---|---|---|
| 로그인 명단 | 대조한다 | Q1: 대조한다 | 없음 |
| 명단 출처 | 미정 | Q4: 보류 | 구현은 테스트용 시드(`scripts/seed-users`)로 시작하고, 실제 명단은 나중에 넣는다 |
| 로그인 유효 시간 | 8시간 | Q5: 보류, 기본 8시간 | 설정값(`SESSION_HOURS`)으로 빼서 나중에 바꿀 수 있게 한다 |
| 이름 저장 | 해시 저장 | Q5: 보류, 기본 해시 저장 | 없음 (기본값대로 구현) |
| 검색 대상 | 블록 | Q3: 블록만 | 없음 |
| FR-1 캐시 | 없음 (요청마다 조회) | 요청마다 조회 | 없음 |

**결론**: 기술 설계는 2단계 명세와 충돌하지 않는다. 바뀐 것은 보류 항목 Q4, Q5를 구현에서 어떻게 다룰지뿐이다.
