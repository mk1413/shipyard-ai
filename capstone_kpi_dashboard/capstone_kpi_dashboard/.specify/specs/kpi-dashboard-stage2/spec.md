## 1. 개요

### 1.1 목적
기준 명세의 KPI 대시보드를 Node.js로 옮기고, 접근 통제(간이 로그인)와 블록 검색을 추가한다. 화면 수치는 현재 Python 버전과 같아야 한다.

### 1.2 범위
- **포함**
  - 기준 명세 FR-1 ~ FR-11 (데이터 로드, 필터, KPI 5종, 직전 기간 비교, 경고, 탭 4개, 원본 데이터)을 Node.js로 옮긴다.
  - FR-12 간이 로그인 (사번 + 이름)
  - FR-13 블록 검색 (SQLite FTS5)
- **제외**: 사내 SSO, 실데이터 연동(MES/ERP), 자동 알림, 데이터 편집, 예지보전
- **고정 값**: 기준일 2026-10-31 (기준 명세 §9)

### 1.3 대상 사용자
- 생산관리 담당자, 현장 관리자, 발표 청중 (기준 명세와 같음)
- 로그인 사용자: 명단에 등록된 사번과 이름을 가진 사람

### 1.4 실행 환경
- Node.js 24 이상, Express 5, EJS 3, `node:sqlite` (내장)
- 실행: `npm start`, 테스트: `npm test`
- 외부 CDN 없음 (원칙 5)

## 3. 요구사항

### 3.1 기준 요구사항 (기준 명세 참조)
기준 명세의 FR-1 ~ FR-11은 그대로 유효하다. 세부 계산식, 상태 판정 표, 탭 구성은 기준 명세 §4를 따른다. 이 명세에서 바뀐 것은 아래 3.2의 FR-1 캐시 문구뿐이다.

### 3.2 바뀐 기준 요구사항
- **FR-1 (바뀜)**: 기준 명세는 "CSV를 읽어 캐시한다"고 적었다. 2단계에서는 요청마다 DB를 조회한다. 데이터가 블록 360행, 생산 360행 규모라 응답에 영향이 작다. 측정 후 필요하면 캐시를 다시 넣는다.

### 3.3 신규 요구사항

**FR-12 간이 로그인**
- 사번과 이름을 입력받아 `users` 테이블의 해시와 대조한다.
- 일치하면 서명 쿠키를 발급한다. 유효 시간은 8시간이다.
- 대시보드(`/`)와 검색(`/search`)은 로그인이 필요하다. 로그인이 없으면 로그인 화면으로 보낸다.
- 실패 문구는 "사번 또는 이름이 일치하지 않습니다" 하나로 통일한다. 사번 존재 여부를 알려 주지 않는다.
- 로그아웃하면 쿠키를 지운다.
- 명단은 `users` 테이블에 미리 등록한다. 등록 방법은 10절의 보류 항목이다.

**FR-13 블록 검색**
- 검색 대상은 블록이다: 블록 ID, 호선 번호, 선종, 공정명.
- 결과는 블록-공정 행이다: 블록, 호선, 선종, 공정, 상태(FR-1 판정 결과).
- 결과는 최대 100건이다.
- 3자 이상 질의는 FTS5 `trigram` 인덱스로 찾는다. 2자 이하 질의는 `LIKE`로 찾는다.
- 빈 질의와 FTS 특수문자(`"`, `*`, `:`, `(`, `)`)는 오류 없이 처리한다.

## 6. 비기능 요구사항

- **사내망 전용**: 외부 CDN, 외부 폰트, 외부 API를 쓰지 않는다 (원칙 5). Plotly.js는 `public/vendor/`에 둔다.
- **한국어 화면**: 사용자에게 보이는 문구는 한국어다 (원칙 4).
- **날짜**: KST(Asia/Seoul)로 표시한다. 데이터는 일 단위라 날짜만 표시한다 (원칙 4).
- **개인정보**: 사번과 이름은 로그와 쿠키에 남기지 않는다 (원칙 3).
- **테스트 먼저**: 공개 함수와 엔드포인트는 테스트가 먼저 있어야 한다 (원칙 1).
- **패키지**: 외부 패키지는 `express`, `ejs`로 제한한다. 나머지는 Node 내장 모듈을 쓴다 (원칙 2).
