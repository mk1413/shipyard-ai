# 프로젝트 헌법 (Constitution)

- 버전: 1.0.0
- 제정일: 2026-11-12
- 최종 개정일: 2026-11-12

이 문서는 프로젝트의 원칙 다섯 개를 정의합니다. 모든 변경(코드, 문서, 설정)은 이 원칙을 지켜야 하며, 원칙을 바꾸려면 아래 "원칙 변경 절차"를 따릅니다.

---

## 원칙 1. 모든 API는 테스트가 먼저 있어야 한다

- **규칙**: 공개 인터페이스(함수, 모듈 API, 엔드포인트)를 구현하기 전에 그 동작을 검증하는 테스트가 먼저 있어야 합니다. 테스트가 실패하는 것을 확인한 뒤 구현합니다.
- **근거**: 대시보드의 KPI 계산은 숫자가 틀리면 발표와 의사결정이 잘못됩니다. 계산 로직을 테스트로 먼저 고정해 두면 리팩터링과 기능 추가 때 값이 조용히 바뀌는 일을 막을 수 있습니다.
- **확인 방법**
  - 명령: `npm test` (내부적으로 `python -m pytest tests -q`) 가 모두 통과해야 합니다.
  - 이력: 새 API를 추가한 커밋에 테스트 파일이 함께 있거나, 테스트 커밋이 구현 커밋보다 앞서 있어야 합니다.
  - 리뷰 항목: 새로 추가된 공개 함수마다 대응하는 테스트가 있는가?
- **적용 범위**: 현재 `kpi_alerts.py`가 해당합니다. `app.py`는 화면 코드이므로 `tests/test_app_smoke.py`로 실행 여부를 확인합니다.

## 원칙 2. 외부 패키지는 꼭 필요한 것만, 추가 이유를 plan.md에 적는다

- **규칙**: `requirements.txt`에 패키지를 추가하려면 꼭 필요해야 하며, `plan.md`에 다음을 기록합니다.
  - 패키지 이름과 버전 범위
  - 용도(어떤 기능에 쓰는지)
  - 표준 라이브러리나 기존 패키지로 대체할 수 없는 이유
- **근거**: 패키지가 많을수록 보안 점검, 업데이트, 사내망 반입 절차 부담이 커집니다. 추가 이유를 남겨 두면 나중에 불필요한 의존성을 걷어내기 쉽습니다.
- **확인 방법**
  - 이력: `requirements.txt`가 바뀐 커밋마다 `plan.md`의 해당 항목이 함께 바뀌어야 합니다.
  - 리뷰 항목: 새 패키지에 대한 근거가 `plan.md`에 있는가?
- **현재 상태**: `pytest>=8`(개발용)이 추가되어 있으나 `plan.md`에 근거가 아직 없습니다. 이 항목은 다음 변경에서 보완해야 합니다.

## 원칙 3. 개인정보(이름, 사번)는 로그에 남기지 않는다

- **규칙**: 이름과 사번은 로그(`print`, `logging`, 예외 메시지, 로그 파일)에 기록하지 않습니다. 식별이 꼭 필요하면 해시 또는 마스킹된 값만 씁니다.
- **근거**: 로그는 여러 사람이 보고 보관 기간도 길어서, 개인정보가 들어가면 유출과 개인정보 보호 위반의 위험이 큽니다.
- **확인 방법**
  - 명령: `grep -rnE "print\(|logging\.|logger\." --include=*.py .` 로 로그 호출을 찾고, 이름·사번 변수가 들어 있지 않은지 확인합니다.
  - 테스트: 로그 출력을 캡처했을 때 이름·사번 값이 나타나지 않음을 검증하는 테스트를 둡니다(해당 기능이 생길 때 추가).
  - 리뷰 항목: 로그 문자열과 예외 메시지에 개인 식별 값이 들어가지 않는가?
- **현재 상태**: 현재 데이터(`data/*.csv`)에는 이름이나 사번 열이 없고, 식별자는 설비·블록 코드입니다.

## 원칙 4. 화면 문구는 한국어, 날짜는 KST로 표시한다

- **규칙**
  - 사용자에게 보이는 문구(제목, 라벨, 경고, 도움말)는 한국어로 씁니다. 기술 용어(OEE, MH 등)는 약어와 함께 한국어 설명을 붙입니다.
  - 날짜와 시각은 KST(Asia/Seoul, UTC+9) 기준으로 표시합니다.
- **근거**: 사용자는 국내 조선소 현장 직원이며, 시간대가 어긋나면 지연일수와 주차 집계가 잘못 보입니다.
- **확인 방법**
  - 리뷰 항목: 새 화면 문자열이 한국어인가? 날짜 표시에 시간대가 명시되었는가?
  - 테스트: 날짜 표시 함수에 대해 기준 시각을 넣고 KST 문자열이 나오는지 검증합니다(해당 함수가 생길 때 추가).
- **현재 상태**: 데이터의 날짜는 시각 없이 일 단위(`2026-09-01`)이며, 시간대 변환 로직은 아직 없습니다. 일 단위 데이터는 KST 기준 일자로 해석하고, 시각이 필요한 표시가 생기면 그때 변환을 추가합니다.

## 원칙 5. 사내망에서만 동작한다. 외부 CDN을 쓰지 않는다

- **규칙**: 실행 시 외부 CDN, 외부 폰트, 외부 API, 외부 스크립트를 불러오지 않습니다. 필요한 정적 자원은 프로젝트 안에 둡니다.
- **근거**: 사내망은 인터넷 접근이 막혀 있는 경우가 많습니다. 외부 자원에 기대면 화면이 깨지거나 로딩이 멈춥니다. 외부로 나가는 요청은 보안 정책 위반이 될 수도 있습니다.
- **확인 방법**
  - 명령: `grep -rniE "https?://|cdn" --include=*.py --include=*.md --include=*.txt --include=*.json .` 를 실행하고, 결과가 문서용 링크(예: `localhost`, 라이브러리 문서)뿐인지 확인합니다.
  - 리뷰 항목: 새로 추가된 URL이 사내 주소이거나 로컬 주소인가?
  - 실행 확인: 인터넷이 차단된 환경에서 `npm start`로 화면이 정상 표시되는지 확인합니다.
- **현재 상태**: 위 명령 결과는 `localhost` 안내문과 pytest 캐시 문서 링크뿐이며, 외부 CDN 호출은 없습니다.

## 원칙 변경 절차

1. **제안**: `constitution.md`의 변경안과 변경 이유, 영향을 받는 코드·문서를 함께 정리합니다.
2. **승인**: 프로젝트 담당자 한 명 이상이 승인합니다.
3. **버전 올리기**: 아래 버전 규칙에 따라 버전을 정하고, 최종 개정일과 변경 이력을 갱신합니다.
4. **반영**: 영향을 받는 코드와 테스트를 고친 뒤 `npm test`가 통과하는지 확인합니다. MAJOR 변경이면 모든 원칙의 확인 방법을 한 번씩 다시 점검합니다.

## 버전 규칙 (MAJOR.MINOR.PATCH)

- **MAJOR**: 원칙을 삭제하거나, 기존 준수 방식을 무효로 만드는 방향으로 의미를 바꿀 때
- **MINOR**: 원칙을 새로 추가하거나, 기존 원칙에 요구사항을 실질적으로 더할 때
- **PATCH**: 문구 명확화, 오타 수정, 예시 추가처럼 요구사항이 바뀌지 않을 때
