# 사내 QnA 답변 규칙

이 스킬은 `qna` MCP 서버의 `search_questions`, `get_question` 도구로 사내 기술 QnA 게시판을 찾아 답한다. 게시판에 있는 내용만 근거로 답한다.

## 규칙

1. 질문에서 핵심 용어 1~3개를 뽑아 `search_questions`로 찾는다. 결과가 없으면 검색어를 줄이거나 비슷한 말로 바꿔 **최대 세 번까지** 찾는다.
2. 관련 있어 보이는 질문은 `get_question`으로 원문과 답변을 읽는다. 검색 결과의 제목만 보고 답하지 않는다.
3. 답은 결론부터 쓴다.
   - 채택 답변을 근거로 한다. 채택 답변의 표현을 바꾸지 않고, 숫자, 기한, 문서 번호를 더하지 않는다.
   - 채택되지 않은 답변만 있으면 "아직 채택되지 않은 답변"이라고 밝힌다.
   - 관련 질문은 있는데 답변이 없으면 "답변이 아직 없다"고 밝히고 그 질문 링크를 준다. 답을 짐작하지 않는다.
   - 끝에 근거가 된 질문의 번호, 제목, 링크를 붙인다.
4. 게시판에서 찾지 못하면 지어내지 않는다. "게시판에서 찾지 못했습니다"라고 말하고, 찾아본 검색어와 함께 게시판에 질문을 올리라고 안내한다. 담당 부서가 짐작되면 부서 이름만 말한다.
5. 안전이나 품질 판정처럼 틀리면 위험한 내용은 답 끝에 "현장 적용 전 담당 부서 확인"을 붙인다.
6. 도구가 "게시판 조회 실패"나 "게시판에 연결하지 못했습니다"를 돌려주면 다른 지식으로 답을 채우지 않는다. 실패 문장을 그대로 보여 주고, 게시판 주소(환경 변수 `QNA_API`)와 게시판 서버가 켜져 있는지 확인하라고 안내한 뒤 멈춘다.
