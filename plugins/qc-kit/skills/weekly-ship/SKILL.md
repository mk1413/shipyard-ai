# weekly-ship

보고 기간: `$ARGUMENTS`

기간이 비어 있으면 진행하지 말고 기간을 물어본다.

이 스킬을 실행하는 메인 대화가 단계 순서와 파일 저장을 맡는다. 에이전트는 파일을 저장하지 않는다(`qc-auditor`는 쓰기 권한이 없다). `out/review.md`는 메인 대화가 쓴다.

## 1단계: 집계 (qc-aggregator)
Agent 도구로 `qc-aggregator`를 부른다. 전달할 내용:
- 보고 기간 `$ARGUMENTS` (검사일 기준으로 자른다)
- 이번이 몇 번째 실행인지(1, 2, 3차)와, 2차 이후라면 직전 감사 지적 전문
- 결과는 `out/summary.xlsx`

집계가 멈추면(판정 열 없음, 판정 값 규칙 밖, 엑셀 잠금 등) 그 이유를 사용자에게 그대로 전하고 여기서 끝낸다.

## 2단계: 감사 (qc-auditor)
Agent 도구로 `qc-auditor`를 부른다. 전달할 내용:
- 보고 기간 `$ARGUMENTS`
- 감사 대상: `out/summary.xlsx`, 원본 `data/`, 규칙 `CLAUDE.md`

감사 결과 전문을 받아 `out/review.md`에 저장한다. 파일 맨 위에 다음을 쓴다:
- 보고 기간, 실행 차수(1차/2차/3차), 실행 시각(오늘 날짜 2026-11-12 기준으로 적는다)
- 그 아래 감사관의 보고 전문 그대로

같은 실행에서 차수가 바뀔 때마다 `out/review.md`에 차수 구분 제목을 붙여 이어 쓴다. 이전 차수 기록을 지우지 않는다.

## 3단계: 판정 분기
감사 결과의 마지막 줄을 본다.
- `판정: 통과` → 4단계로.
- `판정: 반려 (지적 N건)` → 현재 감사가 몇 차수 실행인지 확인한다. 1차 집계 후 재집계는 최대 2회이므로 집계는 최대 3차까지다.
  - 현재가 1차 또는 2차 감사: 지적 전문을 붙여 1단계(집계)로 돌아간다. 차수를 하나 올린다.
  - 현재가 3차 감사(재시도 2회를 모두 쓴 뒤): 문장을 쓰지 않는다. `out/review.md`에 "재시도 2회 후에도 반려, 반려 상태 유지"라고 적고, 남은 지적을 사용자에게 보여준 뒤 멈춘다.
- 마지막 줄이 둘 중 어느 쪽도 아니면 감사 결과를 신뢰하지 않는다. 반려로 취급하지 않고 멈춰서 사용자에게 알린다.

## 4단계: 회의 문장 (qc-writer)
Agent 도구로 `qc-writer`를 부른다. 전달할 내용:
- 보고 기간 `$ARGUMENTS`
- `out/summary.xlsx`와 `out/review.md`의 통과 판정 경로

받은 문장 세 줄을 사용자에게 그대로 보여준다. 출처 목록도 함께 보여준다.

## 마무리
사용자에게 다음을 알린다:
- 실행 차수와 각 차수의 판정(통과/반려 지적 건수)
- 감사관이 반려한 주요 지적(있었다면)
- `out/summary.xlsx`, `out/review.md` 경로
- 확인 필요 항목이 남았는지

커밋은 하지 않는다. 사용자가 요청할 때만 커밋한다.
